1. السبب الجذري للمشكلة
--------------------------------------------------------------------------------
المشكلة: التطبيق يحصل على صلاحية الملفات لكن ملفات .wastickers لا تظهر.

السبب الجذري المثبت بالأدلة (من الفحص، لا من التعليقات):

  RC-1 (الأهم) الكشف كان يعتمد كلياً على Storage Access Framework (SAF).
      ├─ Before: AndroidManifest.xml لم يطلب MANAGE_EXTERNAL_STORAGE إطلاقاً
      │  (النص كان يقول حرفياً "No MANAGE_EXTERNAL_STORAGE ... is requested").
      ├─ ولهذا لم يكن هناك أي مسار يقرأ نظام الملفات مباشرة.
      └─ النتيجة: المستخدم "يمنح الصلاحية" من إعدادات أندرويد، لكن التطبيق
         لا يملك أصلاً آلية تستفيد منها؛ فيبقى يعتمد على MediaStore الذي
         لا يُظهر ملفات التطبيقات الأخرى على Android 11+، وعلى SAF الذي
         يتطلب اختيار كل ملف/مجلد يدوياً.

  RC-2 لا يوجد محرك يفحص المسارات المباشرة (Download/Documents/Pictures/
      Android/media) عبر java.io.File — 0 نتيجة عند البحث في الكود السابق.

  RC-3 لا يوجد تحقق فعلي من الصلاحية: لم يُستخدم
      Environment.isExternalStorageManager() في أي مكان.

  RC-4 لا يوجد تشخيص يميّز "مجلد فارغ" عن "مجلد تعذّر الوصول إليه".
      لذلك كان أي خطأ قراءة يُعرض كقائمة فارغة = "لا توجد ملفات".

  RC-5 الواجهة كانت تعطي الأزرار مساحة أكبر من قائمة الحزم، ولا تعرض
      معاينات حقيقية متعددة، ولا تصفية/ترتيب، ولا شريط إجراءات جماعي.

5. تفاصيل محرك التخزين (Storage Engine)
--------------------------------------------------------------------------------
StoragePermissionManager
  - Environment.isExternalStorageManager() على API 30+.
  - فحص قراءة فعلي (listFiles) كدليل، لا مجرد استعلام.
  - StoragePermissionSnapshot(state, sdkInt, probedRoot, readVerified, detail).
  - settingsIntent() يفتح ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION.
  - إعادة الفحص من onResume عبر LifecycleEventObserver في الواجهة.

AdvancedStorageDiscoveryEngine
  - مسارات ديناميكية: getExternalStorageDirectory + getExternalFilesDirs
    (لاشتقاق جذور التخزين القابلة للإزالة) + /storage enumeration + /storage/emulated/0.
  - لا يوجد مسار مفترض واحد.
  - يجب أن يشمل: Download, Documents, Pictures, Android/media (ضمن الجذور).
  - العمق الافتراضي 8 وحد الملفات 60000 (قابل للتعديل).
  - يمنع تكرار الزيارات بـ canonicalPath.
  - يتجاهل مجلدات الضجيج فقط (.thumbnails, obb, no_backup, code_cache ...)
    ولا يستثني أسماء عامة مثل "files" لتفادي إسقاط حزم حقيقية.
  - لكل مجلد FolderProbeResult: OK / MISSING / DENIED / ERROR
    ← هذا هو الفصل الرسمي بين "فارغ" و"تعذّر الوصول".
  - ملف .wastickers غير قابل للقراءة → DENIED، وليس "غير موجود".
  - لا استثناءات مبتلعة: كل SecurityException/IOException يُسجّل في diagnostics.errors.
  - يعمل على Dispatchers.IO، قابل للإلغاء (currentCoroutineContext().isActive).

WastickersPackageParser
  - VALID فقط إذا: ZIP يُفتح + يحتوي ملصقاً واحداً على الأقل +
    يجتاز Zip-Slip وحدود Zip-Bomb من WastickersArchiveValidator.
  - NEEDS_PARTS لأجزاء الأرشيف المقسّم (.part1 ...).
  - يستخرج حتى 4 معاينات حقيقية (MAX_PREVIEW_BYTES = 512 KB لكل واحدة).
  - يقرأ title.txt / author.txt إن وُجدا.
  - كشف المتحرك من بايتات WebP (ANIM chunk) وليس من الاسم.
  - STATIC / ANIMATED / MIXED / UNKNOWN.
  - مساران: ZipFile (ملف حقيقي) و ZipInputStream (ContentResolver).

9. نتائج تصميم الواجهة الجديدة (WASTICKERS Explorer)
--------------------------------------------------------------------------------
  البنية:
    - Header مضغوط: العنوان + عدد الحزم + حالة الفحص + مؤشر الصلاحية +
      زر تحديث صغير. لا يأخذ ارتفاعاً زائداً.
    - صف بحث واحد رفيع + لوحة تصفية قابلة للإظهار (FilterChip للتصفية،
      AssistChip للترتيب: الأحدث/الاسم/الحجم/عدد الملصقات).
    - البطاقة: معاينة كبيرة نسبتها 1.35 (فسيفساء 2×2 من ملصقات حقيقية
      عند توفر 4 معاينات)، اسم الحزمة، عدد الملصقات، الحجم، شارة النوع،
      حالة الحزمة، ثم زر استيراد صغير بارتفاع 32dp — أصغر من المعاينة.
    - شريط سفلي يظهر فقط عند التحديد أو أثناء الاستيراد (لا أزرار دائمة).
    - Grid متكيّف (GridCells.Adaptive 158dp) → عمودان أو أكثر حسب العرض.
  الحالات: Loading (مع عدّاد ملفات) / Success / Empty (فرق بين فراغ
    التصفية وفراغ القائمة) / Permission Required (زر إعدادات + بدائل) /
    Partial Access (شريط بعدد المجلدات الممنوعة) / Error (سبب + إعادة محاولة).
  التحقق البصري على جهاز فعلي                            : NOT VERIFIED (لا جهاز)
  تحقق RTL/العربية فعلياً على الجهاز                      : NOT VERIFIED (لا جهاز)
